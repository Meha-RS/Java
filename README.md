# Практика 10. Асинхронные вычисления и современная конкурентность

## Задание 1. `Callable` и `Future`
Отправьте вычисление в `ExecutorService`, получите результат через `Future` и корректно завершите пул. Сравните `Runnable` и `Callable`, включая результат и checked exception. Добавьте timeout к `Future.get`. Различайте timeout вычисления и ошибку вычисления; не ждите второй раз без нового бюджета времени. Отмените долгую задачу через `cancel(true)`. Задача должна реагировать на interruption, восстанавливать флаг при невозможности пробросить исключение и освобождать ресурсы. Объясните, почему interrupt — запрос, а не принудительное убийство.

## Задание 2. Последовательное преобразование
Постройте цепочку `supplyAsync` → `thenApply` → `thenAccept` для загрузки и форматирования карточки курса. Зафиксируйте, в каких потоках выполняются стадии и какой executor используется. 
После загрузки пользователя асинхронно загрузите его записи на курсы. Получите плоский `CompletableFuture<List<Enrollment>>`, объясните различие `thenApply` и `thenCompose`.

## Задание 3. `allOf` с сохранением результатов
Загрузите данные для набора course ID. Соберите результаты в исходном порядке, не теряя типизацию. Определите две политики: fail-fast по смыслу и частичный результат с перечнем ошибок.

## Задание 4. Правильный executor
Разделите CPU-bound вычисления и blocking I/O между исполнителями. Продемонстрируйте starvation при неудачной конфигурации и аргументируйте размеры/тип каждого executor. Перепишите blocking-операции на virtual-thread-per-task executor. Сохраните прямолинейный стиль и обычную обработку исключений. Объясните, почему virtual threads повышают масштабируемость ожидания, но не ускоряют CPU-bound код.

## Задание 5. Platform и virtual threads
Проведите воспроизводимый учебный эксперимент с большим числом блокирующих задач. Сравните время, число platform threads и потребление ресурсов. Отделите наблюдение от полноценного benchmark и не используйте 
`sleep` как модель CPU-работы.

## Задание 6. Общий deadline
Несколько подзадач делят один временной бюджет. Перед каждой стадией вычисляйте оставшееся время от монотонных часов, отменяйте ненужную работу и дожидайтесь её завершения. Не используйте preview API; сформулируйте, какую проблему решает structured concurrency.
